# Briefing do Portfolio

Processo para definir escopo antes de escrever código.

## Como funciona

1. **Referências**: você adiciona links e prints em `01-referencias.md` (imagens vão em `refs/`).
   Para cada uma, diga *o que* te chamou atenção. "Gostei do site" não ajuda; "gostei de como o 3D reage ao scroll" ajuda.
2. **Perguntas**: eu leio as referências e faço perguntas em rodadas curtas (3 a 5 por vez).
3. **Decisões**: cada resposta vira uma linha em `02-escopo.md`. Esse arquivo é a fonte da verdade.
4. **Moodboard**: com as decisões fechadas, monto uma página de direção visual (cores, tipografia, motion, 3D) para você aprovar.
5. **Build**: só então criamos o projeto Next.

## Rodadas de perguntas

| Rodada | Tema |
|---|---|
| 1 | Objetivo e público: quem vai ver, o que deve fazer depois de ver |
| 2 | Identidade: tom, personalidade, cores, tipografia |
| 3 | Hero e "primeira impressão": 3D, motion, interação |
| 4 | Conteúdo: seções, projetos (DarkDome primeiro), sobre, contato |
| 5 | Técnico: hospedagem, idioma, CMS ou não, performance e acessibilidade |

## Onde buscar referências

- **Sites premiados**: awwwards.com, godly.website, siteinspire.com, land-book.com
- **Portfolios**: bestfolios.com, Awwwards > categoria Portfolio
- **3D e WebGL**: codrops (tympanus.net/codrops), spline.design/community, threejs.org/examples
- **Design systems**: Vercel Geist, Linear, Radix, shadcn/ui, Apple HIG
- **UI pontual**: mobbin.com, refero.design
